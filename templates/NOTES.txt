The server applies its schema migrations on first boot, so the first rollout
can take a few minutes. Watch it:

  kubectl rollout status statefulset/{{ include "patchmon.server.name" . }} -n {{ .Release.Namespace }} --timeout=10m
  kubectl logs -n {{ .Release.Namespace }} -l app.kubernetes.io/component=server --tail=100 -f

--------------------------------------------------------------------------------
AFTER THE FIRST LOGIN — set the Server URL
--------------------------------------------------------------------------------
Create the admin account, then go to Settings and set the Server URL to:

  {{ include "patchmon.externalUrl" . }}

PatchMon 2.x stores that URL in the database, not in the environment, and it
defaults to http://localhost:3000. It is the address baked into every agent
install command, so until it is correct your hosts cannot register.

--------------------------------------------------------------------------------
Multiple server replicas
--------------------------------------------------------------------------------
Agent connections, the browser SSH terminal, the RDP tunnel and live patch-run
logs are websockets. Enable sticky sessions at your ingress, or they will
reconnect against a different pod on every request:

  nginx.ingress.kubernetes.io/affinity: "cookie"
{{- end }}

What it deploys

Four workloads, one release.

The server needs no persistent volume: agent binaries and the SCAP compliance content ship read-only in the image, and branding assets live in the database. It runs as a StatefulSet because each pod’s stable hostname is what the agent presence registry keys on.

StatefulSet

patchmon-server

The whole application: the /api/* surface and the embedded React SPA on port 3000. Schema migrations run at boot.

Install

From nothing to a running instance.

The chart is published to two places, both carrying the same version built from the same tag — the OCI registry on GHCR, and this classic repository for tooling without OCI support.

classic repository 
# tooling without OCI support
helm repo add patchmon \
  https://fidentity.github.io/patchmon-helm
helm repo update
helm install patchmon patchmon/patchmon --version 2.0.1
OCI registry 
# GHCR, as an OCI chart
helm install patchmon \
  oci://ghcr.io/fidentity/charts/patchmon \
  --version 2.0.1

  1. Supply the secrets

    The chart generates none of them on purpose: a value that changed on every helm upgrade would invalidate every session and make every encrypted column unreadable. Four have to be supplied.

    quick start 
    helm install patchmon patchmon/patchmon \
  --namespace patchmon --create-namespace \
  --set server.env.serverHost=patchmon.example.com \
  --set server.env.serverProtocol=https \
  --set server.jwtSecret="$(openssl rand -hex 64)" \
  --set server.aiEncryptionKey="$(openssl rand -hex 64)" \
  --set database.auth.password="$(openssl rand -hex 32)" \
  --set redis.auth.password="$(openssl rand -hex 32)"

    For anything real, put them in a Secret and reference it — see examples/values-prod.yaml. Keep that Secret in git with SOPS, Sealed Secrets or External Secrets.

    Secrets the chart expects
    SecretRequiredLosing or changing it means
    jwt-secretyesevery session is invalidated
    ai-encryption-keyyesAI credentials, agent bootstrap tokens and notification secrets become unreadable
    postgres-passwordyes—
    redis-passwordyes—
    session-secretnofallback encryption key, used only when ai-encryption-key is unset
    oidc-client-secretwith OIDCSSO stops working

  2. Set the Server URL

    Log in, create the admin account, and set Settings → Server URL to the address your hosts reach PatchMon on. PatchMon 2.x keeps that URL in the database, where it defaults to http://localhost:3000, and it is the address baked into every agent install command. Until you set it, the install commands PatchMon hands out will not resolve for your hosts.

  3. Expose it, with the websocket timeouts

    Agent connections, the browser SSH terminal, the RDP tunnel and live patch-run logs are all websockets. The default ingress annotations raise the nginx proxy timeouts to 86400s — without that, agents show as “connecting” and drop every 30–60 seconds. Traefik needs no configuration; for other controllers, translate the annotations.

Capabilities

Shaped for clusters that stay up.

The defaults are the ones you would have arrived at yourself after the first incident.

Settings the UI can still edit

PatchMon resolves each setting as environment > database > default, and a variable present in the pod spec greys the field out in the UI. So most entries under server.env default to null — set one only when you want the chart to own it.

Horizontal scaling

Supported since PatchMon 2.0: no writeable local volumes, jobs coordinated through Redis and Asynq, agent presence shared over Redis pub/sub keyed on POD_ID. Raise server.replicaCount and turn on sticky sessions.

OIDC and SSO

Issuer, client and scopes, with optional user auto-creation and group→role sync. The redirect URI is derived from your host and printed by helm template, so you can register exactly the right one.

Probes that do not cascade

/health reports on PostgreSQL and Redis as well as the process, so it drives the startup and readiness probes — but never liveness. A 30-second database restart would otherwise fail every replica at once and turn a blip into an outage.

External data stores

Disable the bundled PostgreSQL and Redis and point the chart at managed instances, with the credentials coming from your own Secret. See examples/values-external-services.yaml.

Validated on every push

CI runs helm lint, renders every example, and checks the output against the Kubernetes schemas with kubeconform in strict mode — which catches the fields helm lint does not.
